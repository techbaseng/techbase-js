Phase 1 of 2
switch syntax and break
📖 Concept

switch(expr) compares with === (strict). Each case needs a break or it falls through to the next case (usually a bug). default runs if no case matches. Group cases by omitting break intentionally: case 'A': case 'B': doSame().

script.js
const day = 'Monday';

switch (day) {
  case 'Monday':
  case 'Tuesday':
  case 'Wednesday':
  case 'Thursday':
  case 'Friday':
    console.log('Weekday');
    break;
  case 'Saturday':
  case 'Sunday':
    console.log('Weekend');
    break;
  default:
    console.log('Unknown day');
}

// Without break — fall-through (usually a bug)
switch (1) {
  case 1:
    console.log('one');  // runs
  case 2:
    console.log('two');  // ALSO runs (fall-through!)
  case 3:
    console.log('three'); // ALSO runs
    break;
}

Phase 2 of 2
switch vs if-else and return
📖 Concept

switch is better than long if/else chains when comparing a single value against many constants. Use return inside switch functions to avoid break. Object lookup is often cleaner than switch for mapping values.

script.js
// switch with return (no break needed)
function getLabel(grade) {
  switch (grade) {
    case 'A': return 'Excellent';
    case 'B': return 'Good';
    case 'C': return 'Average';
    case 'D': return 'Pass';
    default:  return 'Fail';
  }
}

// Object lookup — cleaner for many cases
const LABELS = {
  A: 'Excellent', B: 'Good', C: 'Average', D: 'Pass'
};
const label = LABELS[grade] ?? 'Fail'; // ?? for default

// When to use switch:
// ✅ Same variable, multiple constant values
// ✅ Intentional fall-through groups
// ❌ Range checks (use if/else)
// ❌ Regex/complex conditions (use if/else)
