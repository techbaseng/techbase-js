Phase 1 of 2
== vs === and type coercion
📖 Concept

Always use === (strict equality) — checks both value AND type. == (loose equality) does type coercion — converts operands to the same type before comparing. The coercion rules are complex and lead to bugs. Exception: x == null catches both null and undefined.

script.js
// === strict (always prefer this)
5 === 5;       // true
5 === '5';     // false (different types)
null === null; // true
null === undefined; // false

// == loose (avoid — surprising results!)
5 == '5';      // true  (converts '5' to 5)
0 == false;    // true  (both convert to 0)
0 == '';       // true
'' == false;   // true
null == undefined; // true (special case)
null == 0;     // false!
null == '';    // false!
NaN == NaN;    // false (NaN !== NaN)

// Relational operators — also coerce
'5' > 3;       // true ('5' → 5)
'10' > '9';    // false (string comparison: '1' < '9')
'abc' > 'ABC'; // true (char codes)

Phase 2 of 2
Object.is() and NaN
📖 Concept

Object.is(a,b) — like === but handles two edge cases: Object.is(NaN,NaN) is true; Object.is(0,-0) is false. Objects compare by reference, not value: {} === {} is false. Deep equality requires a custom function or library.

script.js
// NaN is never equal to itself!
NaN === NaN;          // false
NaN == NaN;           // false
isNaN(NaN);           // true
Number.isNaN(NaN);    // true (preferred)
Object.is(NaN, NaN);  // true ← use this!

// Positive vs negative zero
0 === -0;             // true (they're equal!)
Object.is(0, -0);     // false (they ARE different)

// Object comparison by reference
{} === {};            // false (different objects)
[] === [];            // false
const a = [1,2,3];
const b = a;
a === b;              // true (same reference)

// Deep equality check (manual)
JSON.stringify([1,2]) === JSON.stringify([1,2]); // true (simple cases)
